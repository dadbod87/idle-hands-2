# Let a neighbor collect a packed snack

The Almost Open Café has a private parcel shelf. A resident with a packed orchard snack can choose another signed-in practice resident and leave one. The recipient can accept, decline or make room by tasting a snack. A parcel can be accepted for 24 hours. The sender can reclaim an unaccepted parcel, including one that was declined or expired. The shelf takes no money and gives no score or timed buff.

The pouch keeps one reserved place while a snack is on the shelf. The sender loses one available snack when leaving it, and the recipient gains one only when the transfer is confirmed. Ordinary harvesting, packing and tasting records keep their existing meaning. The shared pantry uses version 2 after a first transfer with separate offered, received and returned totals. Local browser practice still reads and writes its original version 1 pantry. Cached clients with the previous shared protocol get the reload prompt before a request changes state.

Leaving a parcel locks the two existing resident rows in ID order before creating the row with foreign keys. Accepting, declining or reclaiming locks the acting resident and the exact parcel, and samples the clock after the locks. The sender's remaining pouch capacity comes from the durable, unique outgoing hold. Only relevant pantry packing or collection checks this hold, and other actions and ordinary snapshot reads don't query the shelf. The drawer loads one authenticated, bounded read on open and one after a confirmed action. The read includes the actor's revision and intended sender or recipient. There is no public event, waiting poll, or public score credit. Only registered practice residents can appear in the choice or receive a new parcel.

The focused local browser case uses fictional intercepted snapshots, movement acknowledgments, shelf data and command replies. It checks the drawer at desktop, narrow touch and short 200% text, including a full pouch and an exact retry after a lost reply. Three local pantry tests check older data, occupied capacity and conservation. The standard disposable CI suite must validate the actual transaction rollback, competing acceptance and reclaim, crossed sends, exact expiry, privacy, and browser delivery between two fictional residents. The native browser fixture begins with one legally shaped snack in Fern's pouch. It includes no real account or economy.

After the first native playtest, check whether a small personal notice on returning would help more than asking residents to revisit the shelf. Keep any notice private and event-driven. The source candidate includes a migration file for its isolated test database only. Saved previews, hosted services and current player data are outside this slice.
