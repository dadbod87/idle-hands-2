## Design and authority

A modal receipt reserves72×96pxfor decorative character art, a6.4remkeyboard-scrollable literal status and a permanent Retry row before requests begin. Character illustration is front-facing; it is not world movement or a proximity demonstration. Short action labels,44pxcontrols and wrapping current depot/bag counts adapt to320/360phones,844×390short landscape and doubled root text. Flavor is secondary. aria-disabled plus guarded handlers preserve logical keyboard focus without accepting another command. Only literal text is live-announced; animation frames do not rewrite it.

The pure synthetic model binds confirmation to original command/player/resource/panel/rig. Only a positive matching grant presents quantity once; passive updates, revisions, message strings, stale callbacks and duplicate replies cannot award a receipt. Uncertain replies retain original intent; retry reuses it. Unknown/legacy/mismatched grants stay text-only. Context/hidden/reduced changes cancel motion. A confirmed receipt can be a still image; no animation, decode or failure delays saving or starts another request.

The current real shared API does not supply typed exact per-command quantities. It stores original ok/message/revision, then returns a current snapshot on retry. Subscriptions can update inventory before the awaited reply, and the adapter omits command/replayed provenance. Therefore current snapshot subtraction or human-message parsing is not a safe exact receipt. The proposed future grant must be computed from the locked original action, stored with its immutable result and exposed as optional typed presentation metadata. Old results without it remain text-only. No server/DTO/protocol/migration change is made here; the prototype explicitly supplies fake grants.
