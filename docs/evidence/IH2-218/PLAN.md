# IH2-218 · Load art where it is used

Furniture, workshop fixtures and other room-only artwork were all part of the initial square preparation. Some of the files were intended only for the Bag or a separate art study. The client now asks for each world texture when the room that draws it is entered. DOM menus keep using the same icon files, and the source drawings remain available.

The [texture profile](LOCAL_TEXTURE_PROFILE.json) compares fresh, fixture-free desktop Chromium and 320-pixel touch WebKit sessions on the previous and scoped builds. Each sample opened the square, used the ordinary workshop route, then left by its actual door. Both engines requested 87 distinct SVGs at baseline arrival and 52 with the change. The raw file sizes went from 570,397 to 528,213 bytes. Entering the workshop added 18 drawings and 23,723 raw bytes on its first visit. Returning to the square requested no more SVGs, preserved the workshop save and put the resident at the same front step. Daylight was held for review. These are request counts and raw asset sizes, with no physical-device, loading time, network transfer or production bandwidth claim.

The new cold-arrival browser case requires depot art immediately, and requires the bench, timber illustration, rack, workshop ground and teapot world art on the first real room entry. It checks the ordinary return position and a read-only workshop snapshot. Existing bench, carpentry, allotment, housing, lodging and café reward cases cover textures in actual use. Coffee tests with their own full-suite port use a temporary local copy pointing at the disposable browser-only preview, and stop before any shared-database case.

A targeted equipment test found a separate Bag-to-headwear editor bug introduced by the optional first-morning entry. The click event was reaching the editor as if it were the first-morning callback. `fix/bag-wardrobe-panel-intent` addresses it independently, with native appearance persistence and no first-morning write.
