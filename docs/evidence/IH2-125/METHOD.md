# Comparison method and limitations

The predeclared plan fixes six complete trials, ordered old/current/current/old/old/current. There are three observations per accepted version, not six independent observations of the correction. Neither version nor sample is selected based on its timing. Time-only exit2 remains a completed result; correctness, cleanup, source or target failures stop the sequence. No replacement runs are allowed.

Both clean detached worktrees use the same Node 24.22.2, dependency directory and five accepted profiling files. Their runtime trees differ only in server/http.ts. The existing functional baseline separately proves that an incomplete movement body blocks peers before the correction; the ordinary workload here does not introduce a slow body. Consequently these trials cannot measure the fix's benefit during that failure condition. They investigate ordinary-session observations and variability.

The unchanged profiler uses20 protocol identities, ordinary earned materials, an actual five-second first planter and a queued12-hour kit,140unique committed receipts,100replays, five finite reconnect waves with five re-logins in the second wave and a real30-second idle window. It does not intercept HTTP, grant stock/positions, advance an economic clock or reset normal saved state. Each trial explicitly resets only the named disposable 55434/ih2_load fixture. Cookies and generated child keys stay in memory. The controller never restarts either PostgreSQL container.

The server and driver are separate Node processes. Keep their resource attribution separate. Mean CPU includes deliberately quiet time; RSS is sampled every second and is not an exact peak; event-loop resolution is20ms and includes setup/verification/cleanup. Retained diagnostic observer/sampler work has overhead. Overlapping HTTP/SQL/pool spans are not additive wall time. Open event-stream lifetime is not request latency.

Three per version and a fixed nonrandomized order do not establish causal improvement, absence of a regression, a leak, or capacity. Different worktree paths remain aligned with versions. Compare all observations, ranges and paired directions without treating medians as a guarantee or hiding a threshold miss. The original 500 ms command/replay/snapshot targets and50ms event-loop target are unchanged.

This private-first-lesson workload is not an exact TownClient request model: its explicit snapshot/reconnect sequence is distinct from native stream-open refreshes and public invalidation/coalescing. It does not establish20 rendered browsers, established-player phone input, real devices, Safari, WAN or hosting. Prior Terra desktop/mobile still acceptance belongs to124and is not a visual test of these protocol measurements. No visual runtime change is proposed.

The raw accepted profiler retains its historical “three-run candidate” method label. The outer declared comparison is two cohorts of three in six fixed invocations. Preserve raw metadata and record this distinction rather than rewriting it.

Source acceptance and documentation are distinct: both measured main commits already have independently verified exact-source/raw CI evidence. No game/tool implementation changes or source merge are proposed by this study. A pushed observations branch is an unmerged documentation backup, not a new CI/runtime acceptance result.
