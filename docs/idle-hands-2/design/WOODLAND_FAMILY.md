## Selected small family

Select **pine deadfall → bound hand saw → Garden study easel**, plus an optional **groundskeeper hamper** service and a six-craft shared noticeboard restoration. This connects wood to a recognizable kept furnishing and current produce to repeatable use. Common/birch/oak remain candidates; existing timber is never renamed, converted, made rarer or devalued.

| Candidate | Agent-selected first tuning | Meaning |
|---|---|---|
| Bound hand saw | Free once-only practical lesson; explicitly equip; recover only a missing entitlement | Visible useful hand slot, no sale/trade/maintenance penalty or output multiplier |
| Pine bundles | One personal pool: starts6, cap6, replenishes1/4realhours; carried stack24 | Three varied square-edge deadfall points share this pool; no triple entitlement or competing global tree depletion |
| Garden study easel |4pine +1marigold; one12hfinishing job; explicit claim; candidate owned cap99 | Independent of the old bench. Freestanding pine easel/pressed-flower picture fits one existing furnishing nook. Recognizable earned silhouette and grain; preview/move free |
| Groundskeeper hamper |1pine +2radishes +1marigold; rolling4hservice cooldown | Optional deliberate delivery at an NPC. Private carpentry practice/participation only; no old materials, kits, currency or universal output bonus |
| Town noticeboard | Six opted-in completed craft records, then one fixed24hinstallation deadline | Players retain their easels. One person may record six separate crafts; no unique-helper or simultaneous-login threshold |

The pool is a renewable entitlement to prepare fallen pine, not permission to chop someone else's decorative tree. Essential tool recovery counts owned/equipped copies and cannot create saleable duplicates. Three pine silhouettes/branch piles should feel distinct from current oak/birch/fruit scenery. Later living-tree chopping, birch/oak recipes and new regions require their own art/authority/pacing slice.

A player's **current craft goal** can show that4pine/1flower should be kept for the next easel. It is a planning aid, not a hidden server inventory lock, auto-purchase or forced refusal. Every delivery/request/recipe still previews exact costs and spends only after an explicit confirmation. The player can override the goal. Daily requests are optional; the UI must explain the consequence of spending the last flower.

Private claim is always available. **Record a craft for the noticeboard · keep your easel** is a separate opt-in action, immediately or later. Persist total produced and recorded counts, with recorded≤produced; each completed craft can count once. Public state exposes capped aggregate credits/stage/deadline only, not private owner counts, stock or equipment. The model assumes every helper opts in on claim. Newcomers keep useful personal crafts after the town goal is complete; do not show a further public credit when none is needed. Displaying the easel in a public home remains the owner's explicit placement choice.

## Pacing experiment and selection

The reproducible [woodland model](../../evidence/IH2-066/woodland-model.json) has36schedule/policy/cooldown/absence cohorts and18group/join cases. It reuses actual crop deadlines/seed quotas/capacity in an **independent candidate ledger**; it is not a valid runtime save or authority test. Day0setup is included, visits are uniform, answers/travel/tool lesson time are not modelled, and the optional seven-day absence is day14–21. No automatic repeating job/harvest/order is proposed.

Compare daily-request-first against a reserved personal goal; compare4h/12horder cooldowns. Daily-request-first can consume every daily player's flower and prevent even one easel in42days. Making the selected bundle explicit avoids hiding the personal/civic tradeoff. A visible craft goal helps users understand that choice. The selected **bundled player strategy** reserves the next craft, stops voluntary welcome requests after six (a solo funded-goal proxy), then uses spare ingredients for4horders. Legacy-first keeps making eligible welcome requests indefinitely. These comparisons do not isolate the effect of reservation alone. The runtime continues to allow personal requests after funding; no six-request player limit is proposed. If a daily player keeps spending each flower on those requests, the model does not promise the listed hamper orders. With this explicitly chosen bundle:

## Phone, humor and original-art contract

New actions should begin from the world or a named destination and show the selected node/item, current owned tool, literal cost/output/capacity and one confirm/cancel area. Keep44pxminimum targets, keyboard focus, tap/hover explanations where relevant, explicit disabled reasons and fixed feedback space. Avoid placing a six-line empty status box before every list. New panels should use an action-first summary with a reserved compact feedback strip; IH2-068 addresses existing garden/guide composition rather than silently widening this design task into a UI rewrite.

The humor supports the action: a hand saw is “Certified to divide one problem into two smaller problems”; the easel is “Evidence that you went outside”; a hamper is “Locally sourced. Extensively documented.” Literal cost, cooldown, error and recovery copy stays clear. NPC reactions can change after a first craft, a filled hamper or an opened noticeboard. No joke should require a blocking popup, shame an absent player, identify a real coworker or conceal a failed purchase.

## Authority and migration requirements for067

Current GardenStatev1 conserves harvests as produce plus mixed requests. New recipe/service sinks **cannot** decrement produce then pretend the old schema still validates or forge additional request counts.067 needs an additive versioned consumed-by-use ledger (or equivalently explicit receipts) with per-crop conservation, unchanged old harvest/request/practice history and deterministic v1defaults. Old client/local-save handling must preserve unreadable newer data; test current/cached writers under the existing lock.

New private carpentry state owns the protected tool, pine entitlement timestamps, carried/consumed wood, one finishing job, owned/produced/recorded easels and service cooldown. Original workshop bench/job/material/skill state stays exact. No render-frame income, automatic production repeat, backdated rate bonus or old-currency conversion. Reserve enough output space before spending; a full inventory keeps the completed item/job.

Use the existing signed identity, proximity/context, revision and UUID/payload path. Ingredient debit/job start, claim/owned award and optional anonymous civic record each commit atomically. Retry/stale/full/lost-response/duplicate/last-contribution cases must preserve costs/items; public credits cap at6 and a fixed installation deadline is recorded once. A later visitor cannot edit another home or infer private tool/resource state. Home/workshop furnishing allocation remains once per owned copy. Persist creative work/skills/crops across weekly competition.
