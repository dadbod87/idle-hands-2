# Measure loading street art at first neighborhood entry

The square keeps its illustrated Registry. The test candidate defers 16 street-only SVGs, including the walkable street ground, housing façades, and chimney or verge artwork, until entry into a neighborhood. It leaves furniture, player art, and rules where they were.

One native fixture deliberately holds the street ground image. The actual client starts the neighborhood command only in response to a tap, and its first complete street frame contains the modern Garden Studio and a legacy brick home. The same case covers desktop and a 320-pixel touch viewport. The fictional town intercepts authentication, position, and one existing command. It uses no saved services or real accounts.

The paired loopback comparison used three fresh Chromium contexts per width on each version, with a fixed 75 ms delay on each SVG reply. The square moved from 114 to 98 SVG responses in every sample, shifting 74,736 decoded bytes to the first street visit. The desktop square median moved from 1,098 to 1,092 ms, and the 320-pixel median moved from 1,086 to 1,058 ms. In these samples the combined time to usable square plus first street rose by 112 ms desktop and 103 ms phone. [Exact rows and method](STREET_BOOT_COMPARISON.json).

This candidate is saved as an experiment. The request improvement is deterministic in the sample. The small square timing gain and slower combined trip warrant a more representative connection or an entry-prefetch trial before source promotion.
