# Rehearse the first morning in Ledgerwick

New players currently arrive as a preset resident in the square. Before any combat or persistent custom identity, prove a short first-time experience that makes the resident feel like theirs. The owner requested choosing appearance, a name and a backstory, then waking in a bed. Reuse the four existing original resident rigs for the first rehearsal and add a rented-room illustration. The dormitory is a starting place, separate from permanent homes.

## Player flow

1. Put a chosen name on a small arrival form, select one of four illustrated looks, and optionally inspect each side. The story choices change only the arrival note. The quickest path is name, then Continue.
2. Read one short personal arrival note beside the bed. A deliberate Get up moves the actor to a safe point next to the bed. The short visual beat can be skipped. Reduced motion shows the same final state.
3. Leave by the visible door or an equivalent keyboard/touch action. Land just outside the boarding-house door, facing into the town. Point the resident toward the clerk's existing orientation.

The rehearsal uses fictional in-memory state in a standalone page. It makes no login, game request, durable save, grant or change to a current resident. It demonstrates arrival and room flow while account integration stays a separate task.

## Integration gates

- A real character belongs to one existing account ID. Use a versioned profile and one confirmed opening result per identity. Names are display labels only. Player and recipient selection continue using stable IDs even when names match. Preview/render input as text, allow a bounded range of writing systems, and validate again on the eventual authority.
- Save the opening checkpoint independently of the visual beat. Creation, wake and exit need separate replay-safe intent/result boundaries, with exact matching replay and no receipt for invalid input. Restore the latest accepted checkpoint on reconnect. A delayed old reply cannot reopen the form or move a new resident.
- Existing residents keep their room, projects, crafts, house, appearance and name on update. Existing accounts skip the bed sequence and can later use a deliberate editing service. The boarding-room path grants no house or property, and opening is not a repeat income path.
- Use a coherent position transition through existing collision/door authority. A mounted approach to the actual door and an intentional Enter/Leave action must converge to the same checked arrival. Keep future death recovery separate from this proof.
- Test keyboard, native touch, reduced motion, desktop, narrow mobile and short enlarged text. Measure how much reading someone must do to begin, where a returning player might get stuck, and whether they find the next landmark. Verify no blocked or hidden primary action. Add exact PR/main and server authorization/persistence evidence only when integrating.

The next opportunity after this rehearsal is an opt-in character/lodging candidate for disposable practice identities, with current receipt, room and persistence rules. A larger wardrobe, player photos, physical-phone acceptance, privileged identity changes and deployment each remain separate.
