# Frozen V3 café review

Actual compiled client in default LOCAL mode, with isolated synthetic third-tasting stock and elapsed time, and seeded position at the counter. Chrome emulation at 1440×900, 360×640, 320×640, and 844×390 with 200% root text; no API interception or real profile. These are not physical-device tests.

At each size, review and confirmation produced three total serves and one teapot. The earned/Open bag control was focused, fully visible and at least 44×44 CSS pixels. Status text included the reward and cooldown. In the opened bag, scrolling to the actual illustrated Brave teapot showed 1 owned and 0 placed, with its image loaded. Escape closed the bag, and no page errors were observed. All four contexts requested reduced motion.

A separate 360×640 normal-motion run observed the `cafe-earned` animation running immediately after confirmation and no active animations one second later. A reduced-motion run observed no active animation at the same checks. These are observations, not a precise duration measurement.

No blocker was observed within this scope. The teapot was not placed in the rental or inspected as world art. This check did not exercise the first tasting, empty-stock or error states, focus movement during confirmation, screen-reader announcements, public projection, physical devices, or CI.
