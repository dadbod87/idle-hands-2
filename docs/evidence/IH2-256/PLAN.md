# IH2-256 · Keep the town-map destination picker inside a narrow WebKit dialog

At 320×680 and 200% text, the checked [draft PR #109](https://github.com/dadbod87/idle-hands-2/pull/109) reproduces a five-pixel dialog overflow after the native destination picker has focus. The control itself measures 214 px wide. In WebKit its anonymous native painting contributed 235 px to the parent label. Explicit grid sizing, replacing the label's grid with a block, and restyling the select appearance did not remove the extra intrinsic overflow. Clipping the select's painted overflow keeps the measured dialog boundary at 246 px.

The native select keeps its appearance, focus outline, keyboard selection, popup and full accessible option names. The separate route button repeats the destination and can wrap it. This change is for narrow reading and navigation. It alters no map geometry, locations, presence or authority. The existing test chose the Orchard walk in all four shapes and verified the whole dialog stayed within its width. That exact independent fixture passed WebKit after the fix. Shared observations and movement were intercepted. Physical iPhone and the exact full hosted gate remain outstanding.
